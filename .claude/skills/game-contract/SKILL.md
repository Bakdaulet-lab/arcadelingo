# Контракт мини-игры

## Идея в одном предложении

Игра — это скин над одним контрактом: спросила слово, показала как хочет, доложила
результат. Всё, что сверх этого, ломает возможность добавлять игры, не трогая ядро.

## Цикл

```dart
final item = session.nextItem();
if (item == null) {
  // сессия исчерпана — экран итогов
  return;
}
// показать item.word.text
// варианты ответа = [item.word.translation, ...item.distractors], перемешать
// ... дождаться ответа или таймаута ...
session.report(ReviewOutcome(
  correct: userWasRight,
  responseTime: elapsed,     // при таймауте == timeLimit
  timeLimit: allowedTime,    // сколько игра дала на ответ
  hintsUsed: hintCount,
));
```

`report()` вызывается **ровно один раз** на каждый непустой `nextItem()`. Ни нуля,
ни двух — это самая частая ошибка, и она портит расписание повторов молча. Настоящая
сессия на нарушении бросает `StateError`: `report()` без выданного слова и
`nextItem()` при неотвеченном — баг игры, а не исход, который можно обработать.

## Запрещено

- Импортировать `domain/srs` (проверяется `scripts/arch_check.sh`)
- Решать, какое слово показать следующим, или отфильтровывать выданные
- Придумывать дистракторы: они приходят готовыми, их качество — забота контент-пайплайна
- Хранить прогресс обучения где-то у себя
- Молча пропускать `report()`, когда пользователь вышел из игры на середине —
  либо доложи неответ, либо не бери item; третьего варианта нет

## Обязательно

- `timeLimit` заполнен реальным лимитом этой игры, а не константой из головы:
  по нему SRS нормализует скорость между играми с разным темпом
- Пауза при сворачивании приложения; время на паузе не идёт в `responseTime`
- Игра корректно ведёт себя, когда `nextItem()` вернул `null` на первом же вызове
- Игра не падает, если у слова меньше дистракторов, чем нужно кнопок

## Тесты, без которых игру не принимаем

1. Widget-тест: верный ответ → `report(correct: true)` ровно один раз,
   `responseTime < timeLimit`
2. Widget-тест: таймаут → `report(correct: false)`, `responseTime == timeLimit`
3. Widget-тест: условие конца сессии → игра остановилась, лишних `report()` нет
4. Widget-тест: `nextItem() == null` на первом вызове → экран «на сегодня всё»
5. Голден: минимум три состояния экрана

Для тестов используй фейковую `ReviewSession` со списком заранее заданных `ReviewItem`
и счётчиком вызовов `report()`. Мок здесь не нужен — фейк проще и честнее. Фейк обязан
быть таким же строгим, как настоящая сессия: `StateError` на `report()` без выданного
слова и на `nextItem()` при неотвеченном — иначе тест игры пройдёт с двойным тапом,
на котором настоящая сессия бросит.

## Добавление новой игры

Процедура — `/new-game <имя>`. Эталон для копирования — первая реализованная игра
в `lib/features/games/`; повторяй её структуру, а не изобретай свою.
