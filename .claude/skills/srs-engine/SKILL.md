# SRS-движок Wordarcade

## Инварианты — нарушение любого из них это баг, а не стилистика

1. Всё в `lib/domain/srs/` — чистые функции. `DateTime.now()` внутри **запрещён**,
   текущее время приходит параметром `now`. Проверяется `scripts/arch_check.sh`.
2. Планировщик не знает, из какой игры пришёл результат. Он видит только `ReviewGrade`.
3. Один и тот же вход всегда даёт один и тот же выход. `Random` — только с seed.
4. SRS не пишет в БД, не решает размер сессии, не выбирает игру.

## Шаг 1. Игровой результат → оценка

Игра сообщает сырой факт: верно/неверно плюс время. Перевод в оценку живёт здесь,
в domain, а **не** в игре — иначе каждая новая игра начнёт изобретать свою шкалу.

Нормализуем по лимиту времени, чтобы игры с разным темпом были сравнимы:

```
ratio = responseTime.inMilliseconds / timeLimit.inMilliseconds
```

| Условие | ReviewGrade |
|---|---|
| `!correct` (включая истёкшее время) | `again` |
| `correct && ratio < 0.30` | `easy` |
| `correct && ratio < 0.60` | `good` |
| `correct && ratio >= 0.60` | `hard` |

`hintsUsed > 0` понижает оценку на одну ступень, но не ниже `hard`.
Правильный ответ никогда не даёт `again`.

Крайние случаи — только для верного ответа, неверный остаётся `again`:
`timeLimit == Duration.zero` → трактуем как `hard` (делить нельзя);
`responseTime > timeLimit` → ratio зажимаем в 1.0.

## Шаг 2 (v1). Лейтнер, 5 коробок

Версия для walking skeleton: ~40 строк, полностью тестируемая, никаких магических
констант сверх таблицы ниже.

| Коробка | Когда показать снова |
|---|---|
| 1 | в этой же сессии, не раньше чем через 3 других — «Очередь сессии» ниже |
| 2 | +1 день |
| 3 | +3 дня |
| 4 | +7 дней |
| 5 | +21 день |

Переходы:

- `again` → коробка 1
- `hard` → коробка не меняется, `due` пересчитывается **от `now`**, а не от старого `due`
- `good` → коробка +1 (потолок 5)
- `easy` → коробка +2 (потолок 5)

### Обязательные тест-кейсы (пиши их до реализации)

1. Новая карточка + `good` → коробка 2, `due == now + 1 день`
2. Коробка 5 + `good` → остаётся 5, не 6; `due == now + 21 день`
3. Коробка 5 + `easy` → остаётся 5 (потолок работает и для +2)
4. Коробка 4 + `again` → коробка 1, `due` внутри текущей сессии
5. Коробка 1 + `easy` → коробка 3, а не 2
6. Коробка 3 + `hard` → коробка 3, `due == now + 3 дня` (отсчёт от `now`)
7. Две карточки с идентичным состоянием и одинаковым `now` дают идентичный результат
8. Переход через границу суток и смену часового пояса не меняет номер коробки

### Очередь сессии (`lib/domain/session/`, задача 0.6)

Порядок показа — не расписание: планировщик про него не знает, игра — тем более.
Живёт в `LeitnerReviewSession`:

- **Состав** — один раз на старте, по `now`. Готовые к повтору (карточка с
  `due <= now`), самые просроченные первыми, при равных `due` — порядок сида,
  **не больше `target`**; затем новые слова (карточки нет) в порядке сида, пока
  очередь не наберёт `target`. Не вошедшие остаются нетронутыми до следующей сессии.
  `total` — размер очереди на старте, до конца сессии не меняется.
- Новое слово получает карточку только при `report()`: коробка 1, `due = now`, и
  сразу переход по оценке. Выданное и не отвеченное следов не оставляет.
- **Повтор.** Карточка после ответа в коробке 1 (`again`, а также `hard` на карточке
  коробки 1 — правило по карточке, не по оценке) встаёт на 4-ю позицию очереди, после
  ровно трёх других, **вместо последней не-повторной** карточки — наименее срочной,
  она уйдёт в следующую сессию. Ожидающие повторы невытесняемы. Один повтор на слово
  за сессию. Нет не-повторной карточки на позиции ≥ 4 (впереди меньше четырёх) —
  повтора нет: карточка и так в коробке 1 и всплывёт в следующей сессии.
- `target` задаёт хост (SPEC: 15); время приходит функцией и берётся заново на каждый
  `report()`; состояние уходит колбэком после каждого `report()`, полной картой.

## Шаг 3 (v2). SM-2 — только после Гейта-1

Не трогай, пока Лейтнер не отработал в бою минимум неделю. Апгрейд оправдан, когда
у тебя появятся реальные данные о том, что интервалы промахиваются.

Оценка в шкалу качества SM-2: `again → 2`, `hard → 3`, `good → 4`, `easy → 5`.

```
если q < 3:
    repetitions = 0
    interval    = 1 день
иначе:
    repetitions += 1
    interval = repetitions == 1 ? 1
             : repetitions == 2 ? 6
             : round(previousInterval * easeFactor)

easeFactor += 0.1 - (5 - q) * (0.08 + (5 - q) * 0.02)
easeFactor  = max(easeFactor, 1.3)
```

Стартовый `easeFactor` = 2.5. Нижняя граница 1.3 жёсткая: без неё трудные карточки
уходят в бесконечный цикл однодневных повторов.

Тест-кейсы для v2, дополнительно к переносу кейсов v1: `easeFactor` не опускается
ниже 1.3 после десяти подряд `again`; после `again` следующий успешный ответ даёт
интервал 1 день, а не восстанавливает прежний; округление `interval` детерминировано.

## Чего SRS не делает

Не решает, сколько слов в сессии — это `DailyGoal` в usecases. Не выбирает игру.
Не знает про streak. Не обращается к репозиториям.
