# Установка комплекта

Пять шагов, десять минут. Дальше работаешь через Claude Code.

## 1. Создай Flutter-проект и положи комплект сверху

```bash
flutter create --org com.твойдомен --project-name wordarcade wordarcade
cd wordarcade
# скопируй сюда содержимое этого комплекта, поверх созданных файлов
chmod +x scripts/*.sh
git init && git add -A && git commit -m "chore: стартовый каркас и рельсы Claude Code"
```

`analysis_options.yaml` и `.gitignore` из комплекта заменяют те, что создал
`flutter create` — так и задумано.

## 2. Зависимости — на неделю 1 почти ничего не нужно

Для walking skeleton хватает:

```bash
flutter pub add shared_preferences
```

Всё остальное подключается в Фазе 2, после Гейта-1:

```bash
flutter pub add flutter_riverpod riverpod_annotation freezed_annotation \
                go_router drift drift_flutter flutter_local_notifications flutter_tts
flutter pub add -d build_runner riverpod_generator freezed drift_dev \
                custom_lint riverpod_lint
```

Версии не вписывай руками — `pub add` подставит актуальные. Если Claude предложит
пакет, которого нет в этих двух списках, проси обоснование и проверку на pub.dev.

## 3. Проверь, что рельсы работают

```bash
./scripts/arch_check.sh && echo "арх-гейт ок"
./scripts/verify.sh
```

`verify.sh` на пустом проекте упрётся в отсутствие тестов — это правильное
поведение, а не поломка.

Проверь, что хук реально блокирует: попроси Claude отредактировать любой
`*.g.dart` — он должен получить отказ.

## 4. Настрой Claude Code

```
/statusline     # выведи заполнение контекста и стоимость — это твой датчик топлива
/context        # убедись, что CLAUDE.md подхватился
/hooks          # проверь, что три хука на месте
```

Поставь `gh` CLI и залогинься — Claude умеет через него открывать PR и читать
комментарии ревью.

## 5. Первая сессия

```
Shift+Tab до "plan mode on"

Прочитай CLAUDE.md, ROADMAP.md, SPEC.md и docs/dev/tasks.md.
Мы в Гейте-0. Возьми задачу 0.2 и составь план: какие файлы создаём,
какая структура у words_seed.json, как проверим результат. Код пока не пиши.
```

## Что в комплекте и зачем

| Файл | Роль |
|---|---|
| `CLAUDE.md` | Память проекта. Читается каждую сессию. Держи под 200 строк |
| `ROADMAP.md` | План сборки с гейтами. Обоснование порядка фаз |
| `SPEC.md` | Спека активной фичи. Критерий для ревью |
| `analysis_options.yaml` | Строгие линты; часть правил — ошибки, не подсказки |
| `scripts/arch_check.sh` | Границы слоёв как исполняемая гарантия |
| `scripts/verify.sh` | Единственный гейт «готово» |
| `scripts/hook_*.sh` | Тихий формат после правок, блок записи в генерируемые файлы |
| `.claude/settings.json` | Права и три хука |
| `.claude/rules/*.md` | Правила, скоупленные по путям — не грузятся без нужды |
| `.claude/skills/*/SKILL.md` | Доменные знания по требованию + две вызываемые процедуры |
| `.claude/agents/*.md` | Три ревьюера со свежим контекстом |
| `docs/dev/*.md` | Долгоживущее состояние работы между сессиями |
| `lib/domain/review/review_contract.dart` | Архитектурный ключ: граница ядра и игр |

## Две вызываемые процедуры

- `/ship-check` — предкоммитный ритуал: гейт, ревью субагентами, PR
- `/new-game <имя>` — добавление игры по контракту

Обе с `disable-model-invocation: true`: Claude не запустит их сам и не тратит
на них контекст, пока ты не вызовешь.

## Намеренные ограничения

`flutter test --update-goldens` запрещён настройками прав. Это не придирка:
самый простой способ «починить» упавший голден — перегенерировать его, и тогда
визуальная регрессия проезжает молча. Обновляешь голдены ты, руками, посмотрев
на разницу.

Stop-хук блокирует завершение хода при нарушении границ слоёв. После восьми
подряд блокировок Claude Code принудительно завершит ход — это защита от
зацикливания, закладывайся на неё.
