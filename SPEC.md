# SPEC: Падающие слова (walking skeleton)

Статус: черновик под Гейт-0. Всё, что здесь не описано, — вне скоупа.

## Зачем эта игра первой

Она даёт аркадное ощущение (таймер, давление, комбо) при реализации на обычных
виджетах и `AnimationController`, без игрового движка. И она естественно порождает
`responseTime`, который нужен SRS для оценки уверенности ответа.

## Механика

Английское слово падает сверху вниз. Внизу четыре кнопки с переводами: один верный,
три дистрактора. Игрок жмёт до того, как слово коснётся низа.

- Сессия: 15 слов или 3 потерянные жизни, что наступит раньше
- Время падения: 6 секунд на слово, минус 0.25 с за каждый уровень комбо, минимум 3 с
- Верно: слово рассыпается, +очки × множитель комбо, комбо +1
- Неверно: слово краснеет, верный вариант подсвечивается на 800 мс, комбо сброшено, жизнь −1
- Слово коснулось низа: считается как неверный ответ, жизнь −1
- Экран итогов: счёт, лучшая серия, сколько слов отвечено верно

## Контракт с ядром

Игра работает только через `ReviewSession` (`lib/domain/review/review_contract.dart`).
Она **не знает**, как планируются повторы, и не импортирует `domain/srs/`.

Цикл:

```
final item = session.nextItem();   // null -> сессия исчерпана, показать итоги
// показать item.word.text, кнопки = [item.word.translation, ...item.distractors] в перемешку
session.report(ReviewOutcome(
  correct: ...,
  responseTime: ...,   // при таймауте равно timeLimit
  timeLimit: ...,      // фактическое время падения этого слова
  hintsUsed: 0,
));
```

`report()` вызывается ровно один раз на каждый выданный `nextItem()`.

## Edge cases (каждый — тест-кейс)

1. Слово долетело до низа без ответа → `report(correct: false, responseTime == timeLimit)`, жизнь −1
2. Приложение свёрнуто во время падения → анимация и таймер на паузе, время не начисляется,
   при возврате падение продолжается с той же точки
3. Тап во время подсветки верного ответа (800 мс) → игнорируется, второй `report()` не уходит
4. Двойной быстрый тап по одной кнопке → засчитывается только первый
5. Тап по двум кнопкам в одном кадре → засчитывается только первый обработанный
6. `nextItem()` вернул меньше 15 слов (мало слов к повторению) → сессия честно короче,
   экран итогов показывает фактическое число, без добивки случайными словами
7. `nextItem()` вернул `null` сразу на первом вызове → экран «на сегодня всё», не пустая игра
8. У слова меньше трёх дистракторов → игра не падает; показывает столько кнопок, сколько есть,
   минимум две. Отсутствие дистракторов — проблема контента, а не игры
9. Жизни кончились на 5-м слове → сессия завершается немедленно, `report()` по невыданным
   словам не вызывается

## Вне скоупа

Звук, озвучка слова, анимации частиц, таблица лидеров, настройки сложности, онбординг,
сохранение незавершённой сессии между запусками.

## Проверка, доказывающая, что фича работает

- Widget-тест: верный тап → `report(correct: true)` ровно один раз, с `responseTime < timeLimit`
- Widget-тест: истечение таймера → `report(correct: false, responseTime == timeLimit)`
- Widget-тест: три неверных → сессия завершена, показан экран итогов
- Widget-тест: `nextItem()` вернул `null` на первом вызове → показан экран «на сегодня всё»
- Голден: три состояния экрана (падение, подсветка ошибки, итоги)
- Ручная: собран `--release`, установлен на телефон, сыгран полный круг
