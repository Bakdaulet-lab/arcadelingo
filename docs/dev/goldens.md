# Голдены: как их обновлять

Эталон в этом проекте меняет **человек**, посмотрев на картинку. `flutter test
--update-goldens` не работает: компаратор бросает исключение из `update()`
(`test/golden/flutter_test_config.dart`). Это не перестраховка — автообновление
превращает голден в тест, который всегда зелёный, потому что подстраивается под
код вместо того, чтобы его сторожить.

## Процедура

```
1. flutter test test/golden/

   Красное падение на каждый изменившийся кадр. В тексте — два пути:
   к эталону и к кандидату.

2. Посмотреть глазами:

   test/golden/images/<имя>.new.png     — что код рисует сейчас

   Если кадр менялся, а не создавался впервые, сначала полезнее открыть
   test/golden/failures/<имя>_isolatedDiff.png — он показывает, какие
   именно пиксели разошлись, на чёрном фоне.

3. Решение принимает человек:

   вид верный  →  mv test/golden/images/<имя>.new.png \
                     test/golden/images/<имя>.png

   вид неверный → это найденный баг. Кандидат в мусор, чинится код.

4. flutter test test/golden/     → зелёное

5. git add test/golden/images/*.png
```

`.new.png` и каталог `failures/` в `.gitignore`. Скрипта, который принимает все
кандидаты разом, нет намеренно: ручное переименование — это и есть та пауза, ради
которой запрещён `--update-goldens`.

## Что именно снимается

Восемь кадров, `test/golden/falling_words_golden_test.dart`. Точные моменты
времени — в комментариях к каждому тесту, здесь только зачем каждый нужен.

| Файл | Зачем |
|---|---|
| `falling.png` | обычное состояние игры |
| `reveal_miss.png` | промах, тряска уже улеглась: пара «слово → перевод» по центру |
| `shake.png` | тот же промах на 50-й миллисекунде. Отличается от предыдущего **ровно** сдвигом HUD и кнопок; если однажды поедет и пара, это видно сравнением двух PNG |
| `combo_tint.png` | серия 8: поле подкрашено, кнопки на чистом фоне |
| `score_pop.png` | верный ответ в последний момент: «+15» с меткой ×1.5 и раздутый счёт |
| `word_at_bottom.png` | зазор между словом у низа и верхней кнопкой |
| `summary.png` | итоги |
| `nothing_today.png` | «на сегодня всё» |

Кадров при системном шрифте 2× нет: там открыта **Р7** (игровое поле
переполняется на коротком экране), и эталон закрепил бы сломанную вёрстку как
правильную. Вернуться сюда после Р7.

## Детерминизм: что зафиксировано и почему

- **Шрифты** грузятся из ассетов приложения через `FontManifest.json` — и Rubik,
  и MaterialIcons. Кеш SDK больше не при чём: своя гарнитура приехала в
  `assets/fonts` вместе с задачей 0.12. Загрузчик **падает громко**, если в
  манифесте нет любого из двух семейств: без шрифта `flutter test` рисует каждую
  букву прямоугольником, и эталоны вышли бы зелёными и бессмысленными сразу.
- **Канарейки, их две.** Первая проверяет, что тема просит `Rubik` и что за этим
  именем стоит пропорциональный шрифт (восемь «W» шире восьми «i»). Она уже один
  раз поймала настоящую ошибку: текст стоял вне `Material` и наследовал отладочный
  `monospace` вместо темы.
- Вторая — про **вес**. Rubik вариативный, и обычный `fontWeight` ось `wght` не
  двигает: замерено, строка в `w400` и в `w700` выходит ровно одной ширины. Вес
  идёт через `fontVariations` (`withWeight` в `lib/app/theme.dart`). Порвётся эта
  проводка — весь текст молча уедет в значение файла по умолчанию, а у Rubik это
  Light 300. На картинке такое видно, только если знать, что искать.
- **Платформа темы** запинена в `TargetPlatform.android`: `Typography` выбирает
  гарнитуру по платформе. На результат это сегодня не влияет — `flutter test`
  выставляет `FLUTTER_TEST`, и платформа и так android, — поэтому мутацией пин
  не ловится. Он остаётся как явно названная цель съёмки: то поведение живёт
  внутри `assert`.
- **Экран** — 1080×2340 при плотности 3, то есть 360×780 dp. PNG выходит
  **1080×2340**: `matchesGoldenFile` снимает `RenderView`, а его `paintBounds`
  считаются в физических пикселях. Файл ≈ 50–90 КБ.
- **Масштаб текста** выставлен в 1 явно, иначе унаследовалась бы системная
  настройка машины.
- **Debug-баннер** выключен и в харнессе, и в самом приложении.
- **Порядок кнопок** — `seed: 1`. **Время** — только явными `pump(Δ)`;
  `pumpAndSettle` домотал бы падение до таймаута.
- **Допуска нет.** Расхождение в один пиксель — красное. Эталон смотрит человек,
  и допуск, переживающий сглаживание, пережил бы и настоящий сдвиг.

## Открытый вопрос: другая машина

Голдены сняты на Windows. При появлении CI надо будет выбрать одно из трёх:

- **(а)** пометить голдены тегом и не гонять их на CI;
- **(б)** гонять только на CI и не гонять локально;
- **(в)** ввести допуск на сглаживание.

Вариант «пересоздать эталоны на CI и оставить локальный прогон» **не работает**:
Windows и Linux растрируют текст по-разному, и зелёной будет только одна из двух
машин.
